## 1. 「听」：为什么必须用闭集语法

本机装有 zh-CN 离线识别器（注册表 `HKLM\SOFTWARE\Microsoft\Speech\OneCore\Recognizers\Tokens`）：

- `MS-2052-110-WINMO-DNN` — zh-CN Embedded DNN v11.1（WinRT 用，较新）
- `MS-2052-80-DESK` — SAPI 8.0 桌面识别器（`System.Speech` 用，较老）

用同一段机组复诵（含"修正海压幺洞幺三"），两种用法对比：

| 用法 | 耗时 | 置信度 | 识别结果 |
|---|---|---|---|
| **闭集语法**（3 条候选句） | **69 ms** | 99% | 东方五幺拐五许可放行至济南遥墙按萨桑五号离场初始高度六千九百米应答机四两幺五修正海压**幺洞幺三**东方五幺拐五 |
| 闭集语法（同段，再跑两次） | 46 / 50 ms | 99% | 同上，逐字一致 |
| **开放式听写**（`DictationGrammar`） | **1047 ms** | **32%** | 东方舞妖怪57放行至济南要强安塞桑午后立场初始高度6,900 m印巴几次两药物**修正海牙一动13**东方舞一怪物 |

两件事同时成立：**慢 10~20 倍**，而且**完全不可用**（"东方"→"东方舞妖怪"、
"萨桑"→"安塞桑"、"修正海压"→"修正海牙"）。

原因不难理解：开放式听写要在整个中文词表上搜，而闭集语法只有几条候选，
解码空间小了六七个数量级。**管制通话本来就是闭集**——机组能说的就那么几十句。

### 1.1 语法不用手写：按当前状态现生成

真正好用的地方在于，语法可以**从当前这架飞机的放行内容生成**：

```
正确复诵（1 条）
+ 每个安全关键项各错一位的变体（N 条：高度、应答机、修正海压、程序、目的地…）
```

于是识别器返回的就是"机组到底读的哪一条"，**错项判定等于免费拿到了**：
它返回变体 2，说明海压读错；返回正确那条，才算复诵通过。

实测证据：把海压故意读成 1014（其余不变），闭集里同时放 1013 / 1014 / 高度错三种，
识别器 **94 ms、100% 置信度** 精确返回到 1014 那一条。

这和游戏里已有的 `_readback_items` 逐项判定是**一一对应**的，
所以接起来不是"再加一套判定"，而是"把已有的判定换成语音输入"。

### 1.2 延迟真正花在哪

识别只占 50–100 ms。真正的等待是**等机组说完**（判停/静音检测）。
所以"处理速度"不是瓶颈，方案就是：麦克风 → 判停 → 闭集识别 → 比项。

### 1.3 已落地与待办

**已落地（v0.1.13）**

| 组件 | 作用 |
|---|---|
| `sim/voice_mode.gd` | 转录规范化、通话类型、要素提取、四种回退语义、五项辅助开关 |

## 2. 「说」：为什么不用运行时合成

用户的原话是「我不希望这些声音很人机」。两个思路都试了：

### 2.1 关键一招：过一遍电台链路

真塔台/机载电台是**窄带**（约 300–2700 Hz）+ 压限 + 底噪。
把合成音过一遍这个链路，机械感被抹掉大半，而且**听起来就是"radio"，不是"AI"**：

```
highpass=f=320, lowpass=f=2700,
acompressor=threshold=-20dB:ratio=5:attack=4:release=60,
volume=2.4, alimiter=limit=0.9
```

试听样本：`docs/audio/voice-demo-2026-10.mp3`（第 1 段原始 AI 音色，第 2 段同一句加滤波，第 3 段管制指令）。

### 2.2 为什么不按整句合成

整句合成要**运行时联网调云服务** —— 延迟、要 key、要账号、断网就不能玩，
而且每句话音色会有细微漂移。所以改成**片段拼装**：

- **片段库只有 49 条**：10 个数字 + 21 条固定短语 + 5 个公司呼号 + 4 个离场程序 + 8 个机场
- 实测合计 **284 KB / 38 秒音频**（16 kHz 单声道 Vorbis，已过电台滤波）
- 运行时只是按顺序播几个本地文件：**零延迟、零联网、零 key**
- 音色统一（同一个音色念所有片段，不会一句话一个味）

生成一次随包分发，换引擎只需要重跑生成脚本，`manifest.json` 格式不变。

### 2.3 片段时长是两个坑换来的

1. **合成引擎会在句首句尾留大段静音** —— 单个"洞"能到 1.4 s，
   拼播放就变成一顿一顿的空档。必须 `silenceremove` 削头削尾（areverse 两次削尾）。
2. **单个汉字也被拉长** —— "幺"削完仍是 0.64 s，哪怕把 TTS 语速提到 +45% 也还有 0.49 s。
   一条许可里有 13 个数字，照这个长度整句 17 s，比真塔台的 11 s 慢出明显一截。
   → 用 `atempo`（变速不变调）**按片段类别分开压**：数字 1.35、程序和机场 1.05、短语 1.10。

修完后：单条许可约 **15.7 s**（真塔台约 11 s，仍偏慢但可读），两位说话人两句话合计 29.6 s。

### 2.4 多机组的音色

不需要为每架飞机生成一套音频：Godot 的 `AudioStreamPlayer.pitch_scale`
就能给同一库做出不同的"人"。需要明显区分时再补第二套（管制 / 机组各一套，翻倍到 ~570 KB）。

### 2.5 音色来源与许可证（必须说清楚）

- 目前用 **edge-tts**（微软 Edge 朗读的神经音色，免费、无需 key、离线生成）。
  **只在开发机生成时用，运行时游戏不依赖它，也不把 key 塞进游戏。**
- ⚠️ 但**音频文件本身**是微软音色合成的，用于**分发**时许可证是模糊地带
  （个人项目一般无碍，公开上架建议换）。
- 替代：**Piper**（本地离线开源 TTS）有中文音色，只需另写一个合成后端，
  `sim/voice.gd` 和 `manifest.json` 一个字都不用改。
  这也是为什么逻辑层只认片段 id、不认引擎。

### 2.6 已落地（v0.1.15）

| 组件 | 作用 |
|---|---|
| `sim/voice_library.gd` | 清单、缺件降级、角色分库（管制/机组两套音色）、时长估算、直接读 OGG 成流 |
| `ui/voice_player.gd` | 逐片段播放（片间 45 ms 余量）、新通话顶掉旧的（半双工）、缺片跳过不卡死 |

**片段库不入库**（`.gitignore` 掉 `assets/audio/phrases/`）：

### 2.9 IndexTTS2：本地神经 TTS（2026-10-23 实测）

按需求换了后端：**IndexTTS2**，情绪可控、纯本地、不依赖云端 API。
它是 PyTorch 模型，Godot 里跑不了，所以做成**本地 HTTP 服务**：
`tools/tts_server.py` 提供 `/health` 与 `/tts`，游戏侧 `sim/voice_tts.gd` 用
`HTTPRequest` 要 WAV 字节，`AudioStreamWAV.load_from_buffer` 播出来。

**情绪**：官方 8 维向量顺序是
`[happy, angry, sad, afraid, disgusted, melancholic, surprised, calm]`，
所以「愤怒 70% + 平静 30%」能直接给；`emo_alpha` 再调整体强度。
游戏按通话类型给默认值：申请/复诵/许可以平静为主，没听清加一点意外，质疑加一点点不满。

**本机实测（RTX 4060 Laptop 8GB / torch 2.11.0+cu128 / indextts 2.0.0）**

| 项目 | 结果 |
|---|---|
| 模型体积 | 7.42 GB（`gpt.pth` 3.3G + `s2mel.pth` 1.1G + qwen emo 1.1G） |
| 下载 | ModelScope 直连，3.9 分钟 |
| 冷启动（含加载模型） | 约 40 秒 |
| 短句「许可放行至首都。」 | 首句约 40 秒（冷），后续仍需数十秒 |
| 一整条放行许可 | **114–117 秒**（热） |

**结论：实时合成不适合这个游戏。** 一句许可要两分钟，玩家没法等。
所以最终形态是**离线批量生成**：

- 用 IndexTTS2 生成片段库（与原 `gen_voice.py` 同一套片段 id 与清单格式），
  把音色换成神经 TTS、并按片段给情绪（例如「没听清」带意外）；
- 游戏运行时仍然播预生成片段：零延迟、不占显存、不做模型加载；
- `tts_enabled` 开关保留：调试/演示想听实时合成时可以打开，
  连不上或太慢会自动退回片段库。

**踩过的坑（全部固化进 `tools/setup_indextts2.ps1`）**

1. **Python 必须 3.11**：`indextts` 的元数据写死 `>=3.10,<3.12`，3.12 会被 pip 直接拒绝。
2. **download.pytorch.org 会卡死**：进程有 CPU、临时目录 0 字节。改从上海交大镜像
   `mirror.sjtu.edu.cn/pytorch-wheels/cu128/` 直下（实测 2 MB/s；阿里云只有 170 KB/s）。
3. **装 indextts 会把 CPU 版 torch 2.8.0 再装一遍**，覆盖掉 CUDA 轮子，并留下两个
   `dist-info` 让 transformers 报 `Invalid version: None`。装完必须清掉旧 `dist-info`
   再 `pip install --ignore-installed --no-deps` 强装 cu128 轮子。
4. **torchaudio 2.9+ 的 `save()` 依赖 TorchCodec**（没装就整个合成失败：
   `TorchCodec is required for save_with_torchcodec`）。服务端在没检测到 `torchcodec`
   时把 `torchaudio.save` 换成标准库 `wave` 写法。
5. **BigVGAN 声码器在 ModelScope 上不存在**（404），它会回落 HuggingFace。
   服务端设 `HF_ENDPOINT=https://hf-mirror.com` 才能下到。
6. `use_cuda_kernel` 需要额外编 triton kernel，首次先关掉走纯 PyTorch 路径。

### 2.11 批量生成的实测成本（2026-10-23）

| 项 | 实测 |
|---|---|
| 每片段耗时 | 28–31 秒（含 HTTP + 合成 + ffmpeg 转 OGG） |
| 一套片段库（49 条） | **10–25 分钟**：机组 607 秒（约 10 分钟）、管制 1498 秒（约 25 分钟） |
| 磁盘占用 | 约 365 KB / 套（OGG 窄带 + 电台滤波后） |
| 显存 | 7.8 GB / 8.2 GB，GPU 100%（生成期间别开游戏抢卡） |
| 断点续跑 | `--resume` 跳过已存在片段；**换引擎时不能有旧文件的目录里用 `--resume`**（会把旧引擎的片段当成已完成） |

管制那套慢 2.4 倍是因为参考音色（`assets/audio/voices/controller.wav`）更长，情绪参考向量的推理步数要跟着涨；两套都在同一张卡上跑，期间别开游戏抢显存。

批量生成前**必须先清空目标目录**：edge-tts 时代的 49 个 OGG 文件名与新片段 id 完全一样，
留着它们会让 `--resume` 把整批都跳过（第一轮就踩了这个坑，白等十分钟）。

## 3. 落地顺序建议

1. ~~**先说后听**~~ —— 实际是**先听再说**：听的判定价值更高、语法更规整；
2. 听这边先做**复诵判定**（已完成），再做自由问询（未做）；
3. 两条都留"只用文字"的退路——键盘永远能完成全部操作（已有）。

### 3.1 怎么生成片段库

**先起本地 TTS 服务**（IndexTTS2 在 Python 里，Godot 调不动）：

```powershell
# 起服务（-Mock 表示不加载模型，只验链路；真生成要去掉 -Mock）
powershell -ExecutionPolicy Bypass -File tools\start_tts.ps1 -NoWindow
# 健康检查
curl http://127.0.0.1:8731/health
```

再按角色批量生成（目录里的旧片段要先清掉，见 §2.11）：

```powershell
.venv-tts\Scripts\python.exe tools\gen_voice_indextts.py --role controller
.venv-tts\Scripts\python.exe tools\gen_voice_indextts.py --role pilot
```

片段表（数字/短语/公司/程序/机场）直接读 `sim/voice.gd`，
所以加一条新短语只需要改那一处，生成脚本自动跟上。
情绪按片段给：申请/复诵/许可以平静为主，听不懂带意外，读错带一点不悦。

然后选项 →「语音播报」开关会亮起来（没生成时显示「未生成片段」并禁用）。
旧的 edge-tts 生成脚本 `tools/gen_voice.py` 保留作对照，**不再是主路径**。
