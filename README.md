# 管制模拟器 / Air Traffic Control Simulator

3D 塔台视角的空管模拟游戏。玩家扮演不同管制席位，按真实现场流程逐段推进。

## 设计原则

**仿真逻辑与表现层彻底独立。** 逻辑层零渲染依赖，可以在无头环境跑测试；
表现层（3D 塔台 + UI）只是逻辑层数据的一个"可视化出口"，后期可整体替换画质而逻辑层一行不改。

## 技术栈

| 维度 | 选择 |
|---|---|
| 引擎 | Godot 4.7.2（Forward+） |
| 语言 | GDScript |
| 3D 占位 | 内置 PrimitiveMesh 程序化拼装，后期无缝替换 .glb |
| 资产 | Blender 5.2 无头脚本生成（tools/build_assets.py） |
| 导出 | Godot 内置 Windows 导出预设 |

## 推进顺序

放行 → 地坪 → 地面 → 地勤 → 塔台 → 进近 → 区域管制

一段做扎实再下一段。

## 放行席（Delivery）

第一个可玩的席位。布局照着真实管制席的屏幕来：

```
┌──────────┬────────────────────────────┬──────────────┐
│ 进程单    │  场面监视（机场俯视图）       │ 许可编辑器     │
│ 待放行    │  跑道/滑行道/机坪/停机位      │ SID/高度/应答机│
│ 航班卡片  │  机位上的飞机 + 数据块        │ 发放按钮      │
│          │                            │ 复诵复核       │
│          │                            │ 机场信息卡     │
├──────────┴────────────────────────────┴──────────────┤
│ 陆空通话记录                                            │
└───────────────────────────────────────────────────────┘
```

**场面监视**（`ui/airport_display.gd`）是纯 `_draw()` 绘制的机场俯视图：

| 元素 | 内容 |
|---|---|
| 航站楼 | 主楼 T1 + 南北双指廊，指廊上 18 个登机口刻线（G1–G18） |
| 廊桥 | 近机位到机头的登机桥（带端头），远机位没有 |
| 机位 | A01–A09 北指廊近机位、A10–A18 南指廊近机位、A19–A24 远机位 |
| 机位引导线 | 从机位滑行通道引到每个机位的黄色引导线 |
| 滑行道 | 平行滑行道 A、出口滑行道 B、机坪机位滑行通道 C、三条快速脱离道 |
| 跑道 | 18/36、边线、中线虚线、两端入口条纹、接地区标志、离场方向 |
| 机坪 | 铺面 + 黄色安全边线 + 草地色块 |

一个机位同一时刻只会停一架飞机（`DeliveryDesk._pick_free_stand()` 保证，有断言覆盖）。

- **滚轮缩放**（0.7x ~ 4x，以鼠标位置为锚点，缩放锚点不动）
- **拖拽平移**（左键拖动，超过 4px 阈值才算平移，否则算点击选中）
- **双击复位**
- **点地图上的飞机也能选中**，和点左侧进程单等价

会话界面是**全屏铺满**的：进游戏后底色不透明、塔台窗景隐藏，
不再有背景围一圈。

### 业务链路

```
机组申请 ──► 待放行 ──[发放行许可]──► 已发许可 ──(1.6s)──► 机组复诵 ──► 待复核
                                                               │
                                          ┌────────────────────┴───────────────────┐
                                    复诵一致                                  复诵不一致
                                          │                                        │
                              [复诵正确] 放行完成                    [复诵有误] 退回重发
                                                              点"复诵正确"会被拦下：
                                                              "不能作为放行依据，请重发"
```

- **许可要素**：离场程序（4 选 1）、初始高度（3000/4000/5000/6000 米）、应答机（4 位八进制）
- **应答机校验**：必须 4 位、每位 0-7，输错字符会被输入框直接过滤掉
- **复诵**：1.6 秒后机组复诵自动到达；约 35% 概率读错某一项（应答机/高度/离场程序）
- **读对了却不能放行**：复诵不一致时点"复诵正确"会被拒绝并计入误判数
- **自动来航班**：待放行少于 3 架时，每 18 仿真秒来一架新的
- **席位状态随存档走**：进程单、通话记录、统计都写进 `state.extra["delivery"]`

逻辑在 `sim/delivery_desk.gd`（零界面依赖，55 项断言覆盖），界面在 `ui/delivery_panel.gd`。

## 会话与流程

```
主菜单 ──新游戏/训练──► 席位选择 ──► 加载页 ──► 会话界面 ──保存/载入──► 存档
          │                                        │
          └──继续──► 载入界面 ──► 加载页 ──► 会话界面 ┘
```

- **新游戏**：选席位 → 加载页 → 开局 → 自动存档到 `auto_N` → 进入会话界面
- **训练**：同上，但存档带 `mode=training` 标记，载入列表里显示为「训练」
- **继续**：从任意存档恢复一局（同样经过加载页）
- **会话界面**：顶部是模式/席位/机场/**值班频率**/仿真时钟 + 暂停；中间是席位面板占位；
  底部是「保存游戏 / 载入存档 / 返回主菜单（ESC）」
- **自动存档**：开局写一次到 `auto_N`（崩溃兜底）；后续进度由玩家自己决定存不存
- **退出保护**：返回主菜单时如果有未保存进度，弹三选一确认框
  —— `保存并退出 / 不保存，直接退出 / 取消`。
  刚存完 1 秒内不打扰（`has_unsaved_progress()` 的噪音阈值），
  没手动存过时文案会改成"本局还没有手动保存过"
- **载入保护**：会话内载入别的存档会顶掉当前这局，有未保存进度时同样先问
  —— `保存当前进度并载入 / 不保存，直接载入 / 取消`，文案里带上目标存档名。
  两处保护共用 `main._save_session_now()`，避免保存逻辑走偏
- **保存界面**：填存档名 → 选 8 个手动槽位之一；已有内容需二次确认才覆盖
- 任何对话框打开时**仿真时钟暂停推进**，避免玩家在菜单里"瞎过时间"

## 加载页

`ui/loading_screen.gd`，纯表现层。进度条**不做假**：四个步骤全是真活，
任一步失败就停在加载页上说明原因，不会带着半份数据进游戏。

| 步骤 | 真实动作 |
|---|---|
| 校验会话数据 | 新建会话 / 从存档重建 `GameSession` |
| 载入机场数据 | `AirportData.load_airport()` 解析并校验 JSON |
| 绑定席位与频率 | 取出该席位的甚高频频率、主跑道，写入会话 |
| 进入塔台 | 切换界面，淡出加载页 |

步骤之间有一小段停顿（`_pace()`），目的只是让进度条能被看见 —— 代码注释里写明了，
不假装在干活。右侧的扫描雷达是纯装饰，没有任何数据含义。

有 `_booting` 防重入：加载中再点一次"新游戏"不会起第二局。

## 机场数据

`data/airports/<id>.json`，由 `core/airport_data.gd` 加载并**校验结构**：

- `id` / `name` 必填
- `runways` 必须是非空数组，每条要有 `id` 和正数 `length_m`
- `frequencies` 必须包含 `delivery / ground / tower / approach / center`

校验失败直接报错停下，不"尽力而为"地用半份数据 —— 否则后面席位逻辑里
少一个频率字段会莫名其妙地空着，很难查。

⚠️ **导出 exe 时要把 `*.json` 加入包含过滤器**，否则 `data/` 不会被打包。
本机验证过：`data/airports/*.json` 没有被 Godot 当作资源导入（无 `.import`），
是普通文件。

## 存档系统

存档属于**逻辑层**，零渲染依赖，可无头测试。

```
core/save_format.gd   格式契约（magic / 版本号 / 槽位规则 / 席位名）
core/save_store.gd    磁盘层：原子写、校验、列举、删除
core/airport_data.gd  机场数据加载与校验
sim/save_game.gd      元信息 + 校验和 + 版本校验 + 迁移入口
sim/sim_state.gd      仿真状态根对象（可完整序列化）
sim/game_session.gd   一局游戏（活的），存档是它的快照
ui/load_screen.gd     载入界面（列表 / 载入 / 二次确认删除）
ui/save_screen.gd     保存界面（命名 / 选槽 / 二次确认覆盖）
ui/seat_picker.gd     开局前的席位选择
ui/loading_screen.gd  进入游戏的加载页
ui/confirm_dialog.gd  通用三选一确认框（退出保护等）
ui/session_screen.gd  会话 HUD
```

### 三条硬规则

1. **原子写** —— 先写 `.tmp`，核对长度，旧的改名为 `.bak`，最后 rename 提交。
   任一步失败都回滚，不会留下半截存档。
2. **只读不崩** —— 任何异常都变成 `{ok:false, error:"人话"}`，损坏的存档仍会
   出现在列表里并标红，而不是静默消失。
3. **路径安全** —— 槽位 id 必须过 `SaveFormat.is_valid_slot_id`，
   杜绝 `../` 穿越。

### 一个踩过的坑

Godot 的 `JSON.parse_string` 会把**所有数字都读成 float**，于是写入时是 int 的
`1760000000`，读回变成 `1760000000.0`，两次 `stringify` 结果不同、校验和永远对不上。
解法是在算校验和之前先跑 `SaveGame._normalize()`，把"没有小数部分的浮点"压回 int。

### 存档位置

```
%APPDATA%\Godot\app_userdata\管制模拟器\saves\slot_<id>.json
```

## 版本与发布（按版本号分支，不覆盖旧版本）

每个版本都固定成一个独立分支 `vX.Y.Z` 和一个同名 tag，**创建后永不再改动**，
所以任何一版都能随时取回：

```
main       最新版本（持续开发）
v0.0.1     已固定，不再改动
v0.0.2     已固定，不再改动
```

版本号只有一个来源：`core/version.gd` 里的 `MAJOR / MINOR / PATCH`。

发布流程：

1. 改 `core/version.gd` 把版本号加一
2. 提交所有改动（工作区必须干净）
3. 运行 `powershell -ExecutionPolicy Bypass -File tools\release.ps1`

脚本会读出版本号，建立并推送 `vX.Y.Z` 分支与 tag。
**如果该版本分支或 tag 已存在，脚本直接拒绝退出**（不会用 -f 覆盖）。

先看会发生什么、不真正推送：

```
powershell -ExecutionPolicy Bypass -File tools\release.ps1 -DryRun
```
