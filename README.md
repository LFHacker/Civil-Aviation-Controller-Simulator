# 管制模拟器 / Air Traffic Control Simulator

3D 塔台视角的空管模拟游戏。玩家扮演不同管制席位，按真实现场流程逐段推进。

## 设计原则

**仿真逻辑与表现层彻底独立。** 逻辑层零渲染依赖，可以在无头环境跑测试；
表现层（3D 塔台 + UI）只是逻辑层数据的一个"可视化出口"，后期可整体替换画质而逻辑层一行不改。

## 技术栈

| 维度 | 选择 |
|---|---|
| 引擎 | Godot 4.7.2（Forward+） |
| 语言 | GDScript |
| 3D 占位 | 内置 PrimitiveMesh 程序化拼装，后期无缝替换 .glb |
| 资产 | Blender 5.2 无头脚本生成（tools/build_assets.py） |
| 导出 | Godot 内置 Windows 导出预设 |

## 推进顺序

放行 → 地坪 → 地面 → 地勤 → 塔台 → 进近 → 区域管制

一段做扎实再下一段。

## 放行席（Delivery）

第一个可玩的席位。布局照着真实管制席的屏幕来：

```
┌──────────┬────────────────────────────┬──────────────┐
│ 进程单    │  场面监视（机场俯视图）       │ 许可编辑器     │
│ 待放行    │  跑道/滑行道/机坪/停机位      │ SID/高度/应答机│
│ 航班卡片  │  机位上的飞机 + 数据块        │ 发放按钮      │
│          │                            │ 复诵复核       │
│          │                            │ 机场信息卡     │
├──────────┴────────────────────────────┴──────────────┤
│ 陆空通话记录                                            │
└───────────────────────────────────────────────────────┘
```

**场面监视**（`ui/airport_display.gd`）是纯 `_draw()` 绘制的机场俯视图：

| 元素 | 内容 |
|---|---|
| 航站楼 | 主楼 T1 + 南北双指廊，指廊上 18 个登机口刻线（G1–G18） |
| 廊桥 | 近机位到机头的登机桥（带端头），远机位没有 |
| 机位 | A01–A09 北指廊近机位、A10–A18 南指廊近机位、A19–A24 远机位 |
| 机位引导线 | 从机位滑行通道引到每个机位的黄色引导线 |
| 滑行道 | 平行滑行道 A、出口滑行道 B、机坪机位滑行通道 C、三条快速脱离道 |
| 跑道 | 18/36、边线、中线虚线、两端入口条纹、接地区标志、离场方向 |
| 机坪 | 铺面 + 黄色安全边线 + 草地色块 |

一个机位同一时刻只会停一架飞机（`DeliveryDesk._pick_free_stand()` 保证，有断言覆盖）。

- **滚轮缩放**（0.7x ~ 4x，以鼠标位置为锚点，缩放锚点不动）
- **拖拽平移**（左键拖动，超过 4px 阈值才算平移，否则算点击选中）
- **双击复位**
- **点地图上的飞机也能选中**，和点左侧进程单等价

会话界面是**全屏铺满**的：进游戏后底色不透明、塔台窗景隐藏，
不再有背景围一圈。

### 业务链路

```
机组申请 ──► 待放行 ──[发放行许可]──► 已发许可 ──(1.6s)──► 机组复诵 ──► 待复核
                                                               │
                                          ┌────────────────────┴───────────────────┐
                                    复诵一致                                  复诵不一致
                                          │                                        │
                              [复诵正确] 放行完成                    [复诵有误] 退回重发
                                                              点"复诵正确"会被拦下：
                                                              "不能作为放行依据，请重发"
```

- **许可要素**：离场程序（4 选 1）、初始高度（3000/4000/5000/6000 米）、应答机（4 位八进制）
- **应答机校验**：必须 4 位、每位 0-7，输错字符会被输入框直接过滤掉
- **复诵**：1.6 秒后机组复诵自动到达；约 35% 概率读错某一项（应答机/高度/离场程序）
- **读对了却不能放行**：复诵不一致时点"复诵正确"会被拒绝并计入误判数
- **自动来航班**：待放行少于 3 架时，每 18 仿真秒来一架新的
- **席位状态随存档走**：进程单、通话记录、统计都写进 `state.extra["delivery"]`

逻辑在 `sim/delivery_desk.gd`（零界面依赖，55 项断言覆盖），界面在 `ui/delivery_panel.gd`。

|---|---|

### 审查飞行计划（机制规范 §1）

进程单上的「审查飞行计划」会打开一个独立窗口：左边是待审查航班，右边是该航班的
**字段对照表**，逐行给出「计划值 / 当前有效值 / 比对结论 / 处置」。

| 字段 | 计划值 | 当前有效值 |
|---|---|---|
| 起降机场 | 飞行计划 | 本场 ICAO |
| 航路 | 飞行计划 | 该 SID 在当前航路结构里对应的航路 |
| 机型 | 飞行计划 | 机型库 |
| 尾流类别 | 飞行计划 | ICAO Doc 8643 口径（机型库） |
| 备降场 | 飞行计划 | 当前可用备降场清单 |
| 初始高度 | 飞行计划 | 该 SID 的管制协议高度带（LOA） |
| 起飞重量 / 续航时间 | 飞行计划 | 只显示，不参与判定 |

三种处置：

- **修正**：把计划值改成当前有效值（**会真的改到航班字段上** —— 高度/航路这些会进许可，
  只在表格里改数字等于没改）。
- **协调**：5–15 秒后落地，期间该行显示"协调中…"，同一项不能重复提交。
- **保留**：标记为已审查（有保留），不动数据。

规则：还有未处置的不一致项时，「完成审查」置灰；审查完成后进程单状态从「已申请」
变成「计划已审查」（七态见下）。演示机场的计划里故意留了两处真实的不一致
（CES2302 尾流写错、CES3305 高度超出协议带），不是写死的假数据。

数据来源分离得比较干净：判定规则在 `sim/plan_review.gd`（零界面依赖，66 项断言），
参照数据在 `data/airports/*.json` 的 `review_ref`，窗口只管显示。

### CDM 时隙与放行顺序（机制规范 §2）

每架航班带四个时间，进程单上只读显示：**EOBT**（来自计划）、**TOBT**（承运人/地面服务）、
**CTOT**（受流量限制才有时隙，单独标色）、**COBT**（CTOT 反推的撤轮挡时刻，= CTOT − 12 分钟滑行）。

- 演示机场里约 45% 的航班受 CTOT 约束（由随机种子决定，同一局可复现）。
- **拖动进程单可调整放行顺序**：按住卡片拖动，松开按落点落位。
- 受约束航班**不会被排到"时隙更早的受限航班"前面** —— 那等于抢别人的时隙。
  被拒绝时卡片弹回，提示写清是谁的时隙挡着。
- **早于 CTOT 不许放行**：复核 时会直接返回"受 CTOT 0842 约束，最早放行时间 0842（现在 0815）"。
- 放行时刻会相对时隙记一个结果：**提前 / 准时 / 延误**（±3 分钟内算准时），进评分。

### 许可闸门与数值校验（机制规范 §5.1 / §10）

- **QNH 必须由管制员确认**：机组报告已抄收 ATIS 也不是省掉高度表拨正值的理由，
  许可编辑器里有「确认 QNH」按钮，没确认时发放行许可按钮置灰。
- **应答机重复**：与空域里另一架（已发许可且未移交）重复时拒绝发放，并点名占用者。
- **高度必须在 SID 的协议高度带内**：超出拒绝，提示里给出上下限。

### 通播生命周期（机制规范 §3）

- **代号就是版本指针**：按字母推进，Z 之后回到 A，玩家不能跳字母。
- **有效期**：满 50 分钟算「即将过期」，满 60 分钟算「已过期」（跨零点也算对）。
- **重大变化阈值**（《通播 ATIS 介绍》）：风向变化 ≥60° 且两边风速均 ≥5 m/s、
  能见度跨越 800 米 —— 触发时通播卡亮「⚠ 重大变化」并写进通话记录。
- **过期后果**：过期后发放行许可直接被拒（"通播 X 已过期，请先…"），
  必须先做两件事之一：**通知最新通播** 或 **逐项通报变化**（都在通播卡上），做了才放行。
- 通播卡就在右栏机场信息上方，显示 B 有效（12 分钟前发布）。
- 更新目前是「按实况更新」（一键把实况写进通播）。
  ⚠️ 规范 §3.2 要求的**可编辑表单**（玩家能选错值 → 通播有误 → 后续特情）还没做，
  逻辑层 update_atis(opts) 已经支持写错值并标记 has_error，只缺界面。

### 许可发布三模式与离场情报（机制规范 §5）

三种模式在「选项」面板里切换（与难度并列），设置持久化：

| 模式 | 玩家做什么 |
|---|---|
| **预设一键** | 按计划 + 运行要素自动生成完整许可，点「一键发送预设许可」即可 |
| **填空式**（默认） | 选 SID / 高度 / 应答机，点「发放行许可」 |
| **自由文本** | 输入完整一句话，系统用**关键词 + 数值**解析七项要素；缺哪项就说哪项 |

自由文本校验示例：缺少呼号 XXX / 缺少放行界限 ZBAA / 没有识别到离场程序 /
没有识别到初始高度 / 缺少修正海压 1013。应答机扫描会避开高度数字。

**离场情报勾选区**（机组没抄 ATIS 时出现）：使用跑道 / 风向风速 / 能见度 /
修正海压 / 地面滑行路线 / 跑道视程 / 低空风切变，逐项勾选或「全部通报」。
机组已抄收现行 ATIS 的可省略项自动标为覆盖，**修正海压永远要单独确认**。
漏报的条数记在航班上（dep_info_skipped），进评分扣分。

### 难度分级（机制规范 §0.3）

「选项」面板里三选一，持久化到 user://settings.cfg 的 [game] 段：

- **简易**：审查计划自动标红项、只能「修正计划」；复诵直接给对错；移交自动打勾
- **进阶**（默认）：审查要自己发现；复诵还是系统给结论；移交自动打勾
- **高阶**：审查不标红（漏检进评分）、复诵要逐项自己判 + 60 秒时限、
  移交要逐项确认 + 90 秒超时标记

### 复诵核对（机制规范 §6）

机组复诵到达后，右侧显示**逐项比对表**：项目 / 许可 / 复诵 / 判定。

- **关键项**（不一致必须拦）：使用跑道、离场程序、航路、初始高度、应答机、修正海压、离场频率
- **非关键项**（只记录不阻断）：地面风、能见度
- **简易模式**（默认）：系统直接给出 ✓一致 / ✕不一致；有红项时「复诵正确」置灰，只能重发。
- **高阶模式**（desk.readback_hard = true）：**不给结论**，每项显示「未核对」，
  玩家自己点成「一致 / 不一致」；全部判完才能确认；有 **60 秒时限**，
  超时退回「计划已审查」、需重新发布许可。
  把实际不一致的项标成「一致」**不拦截**，但记进 missed_readback（规范 §6.2 原话：
  系统不拦截，后续飞行阶段触发告警）。
- 纠错一律**重发完整许可**，不能只改一项（现有 eissue 就是这个语义）。

⚠️ 难度开关目前还没有设置界面，只能通过逻辑层字段切换；设置页会在做「难度分级」时补。

### 移交地面（机制规范 §7）

放行完成后右侧出现**移交地面检查**卡，五项逐条打勾：

| 检查项 | 满足条件 |
|---|---|
| 飞行计划已审查 | checked |
| 放行许可已发布 | 状态 ≥ 许可已发布 |
| 复诵已确认 | 状态 = 复诵已确认 |
| 修正海压已确认 | 玩家点过「确认 QNH」 |
| 通播状态已核对 | 通播未过期，或机组已被处置过 |

- **简易模式**：系统按状态自动打勾，全绿才让点「移交给地面席」。
- **高阶模式**（desk.handoff_hard = true）：不打勾，要逐项点「确认」；
  不满足的项点不了；从复诵确认起 **90 秒**内没移交，打「移交超时」标记（不阻断，扣分）。

### 整理进程单（机制规范 §4）与运行品质评分（§11）

- 进程单下方「整理进程单」：按计划时刻重排、清掉已移交航班的排序位，
  **2 秒冷却**，不改变任何航班的状态与数据。
- 左栏底部实时显示 已放行 N 架 · 已移交 N 架 · 评分 X (等级)。
  评分明细（desk.score_report().lines）：

| 行为 | 分值 |
|---|---|
| 按时放行（提前/准时） | +2 / 架 |
| 干净移交 | +1 / 架 |
| 顺序调整导致延误 | −1 / 架 |
| 复诵漏检（高阶误判） | −3 / 项 |
| 计划异常漏检（高阶） | −2 / 项 |
| 移交超时 | −1 / 架 |
| 复诵核对超时 | −2 / 次 |
| 误判复诵（简易） | −1 / 次 |
| 通播要素与实况不符 | −3 / 次 |

评分不判负，只决定星级/绩效：≥10 → A，≥1 → B，其余 C。

### 放行席状态机（机制规范 §0.2）

```
等待申请 → 已申请 → 计划已审查 → 许可已发布 → 复诵待确认 → 复诵已确认 → 已移交地面
```

内部仍用 4 个枚举 + `checked` / `handed_off` 两个标记表示，`Flight.flow_state()`
换算成上面七态的序号（§0.2 的对外口径），`state_text()` 直接给出中文标签。
这样既满足规范，又不用去改一遍所有调用点（改枚举会波及存档与全部测试）。

## 会话与流程

```
主菜单 ──新游戏/训练──► 席位选择 ──► 加载页 ──► 会话界面 ──保存/载入──► 存档
          │                                        │
          └──继续──► 载入界面 ──► 加载页 ──► 会话界面 ┘
```

- **新游戏**：选席位 → 加载页 → 开局 → 自动存档到 `auto_N` → 进入会话界面
- **训练**：同上，但存档带 `mode=training` 标记，载入列表里显示为「训练」
- **继续**：从任意存档恢复一局（同样经过加载页）
- **会话界面**：顶部是模式/席位/机场/**值班频率**/仿真时钟 + 暂停；中间是席位面板占位；
  底部是「保存游戏 / 载入存档 / 返回主菜单（ESC）」
- **自动存档**：开局写一次到 `auto_N`（崩溃兜底）；后续进度由玩家自己决定存不存
- **退出保护**：返回主菜单时如果有未保存进度，弹三选一确认框
  —— `保存并退出 / 不保存，直接退出 / 取消`。
  刚存完 1 秒内不打扰（`has_unsaved_progress()` 的噪音阈值），
  没手动存过时文案会改成"本局还没有手动保存过"
- **载入保护**：会话内载入别的存档会顶掉当前这局，有未保存进度时同样先问
  —— `保存当前进度并载入 / 不保存，直接载入 / 取消`，文案里带上目标存档名。
  两处保护共用 `main._save_session_now()`，避免保存逻辑走偏
- **保存界面**：填存档名 → 选 8 个手动槽位之一；已有内容需二次确认才覆盖
- 任何对话框打开时**仿真时钟暂停推进**，避免玩家在菜单里"瞎过时间"

## 窗口与显示

主菜单页脚和游戏内顶栏都有「窗口」按钮，点开是这套设置（改完立刻生效，**下次启动沿用**）：

| 项 | 说明 |
|---|---|
| 显示模式 | `窗口` / `全屏`（无边框，切回来不掉分辨率）/ `独占全屏` |
| 窗口尺寸 | 1280×720 / 1600×900 / 1920×1080，全屏时自动置灰 |
| 显示器 | 只有接了多块屏才出现，可选「跟随系统」或钉在某块屏上 |
| 置顶显示 | 窗口永远压在其它程序上面（边看录像/文档边练时用） |
| 最小化窗口 | 收进任务栏 |
| 新开一个窗口 | 再启动一份程序 —— 双屏时可以一块屏放行席、一块屏地面席 |
| 恢复默认 | 回到 `窗口 + 1280×720 + 不置顶 + 跟随系统` |

- 配置存在 `user://settings.cfg`（Windows 下是
  `%APPDATA%\Godot\app_userdata\管制模拟器\settings.cfg`）
- **配置坏了也必须能开**：文件缺失、内容非法、数值越界都退回安全默认值，
  尺寸还会先夹进显示器可用区域，不会出现"窗口一半在屏幕外"
- 逻辑与界面分家：`core/window_settings.gd` 只做存取/校验/套用，
  `ui/window_menu.gd` 只做按钮和面板；`DisplayServer` 调用集中在 `apply()` 里，
  无头测试时整段跳过（`tests/test_window.gd`，37 项断言）

| 面板 | 收起后看不到什么 |

| 陆空通话记录 | 底部陆空通话 |

| 席位与频率 | 左上角「训练 · 放行席 · DEMO · 121.950」 |
| 仿真时钟 | 顶栏时钟 |

三套布局预设 + 恢复默认：

| 预设 | 收起 |
|---|---|
| 标准席位 | 什么都不收 |
| 紧凑 | 通话记录、席位徽章 |

- 逻辑与界面同样分家：`core/view_state.gd` 只做存取/校验/预设（无头可测），
  `ui/view_menu.gd` 只做菜单，`ui/session_screen.gd` + `ui/delivery_panel.gd`
  负责把布尔值变成 `visible`。

## 加载页

`ui/loading_screen.gd`，纯表现层。进度条**不做假**：四个步骤全是真活，
任一步失败就停在加载页上说明原因，不会带着半份数据进游戏。

| 步骤 | 真实动作 |
|---|---|
| 校验会话数据 | 新建会话 / 从存档重建 `GameSession` |
| 载入机场数据 | `AirportData.load_airport()` 解析并校验 JSON |
| 绑定席位与频率 | 取出该席位的甚高频频率、主跑道，写入会话 |
| 进入塔台 | 切换界面，淡出加载页 |

步骤之间有一小段停顿（`_pace()`），目的只是让进度条能被看见 —— 代码注释里写明了，
不假装在干活。右侧的扫描雷达是纯装饰，没有任何数据含义。

有 `_booting` 防重入：加载中再点一次"新游戏"不会起第二局。

## 机场数据

`data/airports/<id>.json`，由 `core/airport_data.gd` 加载并**校验结构**：

- `id` / `name` 必填
- `runways` 必须是非空数组，每条要有 `id` 和正数 `length_m`
- `frequencies` 必须包含 `delivery / ground / tower / approach / center`

校验失败直接报错停下，不"尽力而为"地用半份数据 —— 否则后面席位逻辑里
少一个频率字段会莫名其妙地空着，很难查。

⚠️ **导出 exe 时要把 `*.json` 加入包含过滤器**，否则 `data/` 不会被打包。
本机验证过：`data/airports/*.json` 没有被 Godot 当作资源导入（无 `.import`），
是普通文件。

## 存档系统

存档属于**逻辑层**，零渲染依赖，可无头测试。

```
core/save_format.gd   格式契约（magic / 版本号 / 槽位规则 / 席位名）
core/save_store.gd    磁盘层：原子写、校验、列举、删除
core/airport_data.gd  机场数据加载与校验
sim/save_game.gd      元信息 + 校验和 + 版本校验 + 迁移入口
sim/sim_state.gd      仿真状态根对象（可完整序列化）
sim/game_session.gd   一局游戏（活的），存档是它的快照
ui/load_screen.gd     载入界面（列表 / 载入 / 二次确认删除）
ui/save_screen.gd     保存界面（命名 / 选槽 / 二次确认覆盖）
ui/seat_picker.gd     开局前的席位选择
ui/loading_screen.gd  进入游戏的加载页
ui/confirm_dialog.gd  通用三选一确认框（退出保护等）
ui/session_screen.gd  会话 HUD
```

### 三条硬规则

1. **原子写** —— 先写 `.tmp`，核对长度，旧的改名为 `.bak`，最后 rename 提交。
   任一步失败都回滚，不会留下半截存档。
2. **只读不崩** —— 任何异常都变成 `{ok:false, error:"人话"}`，损坏的存档仍会
   出现在列表里并标红，而不是静默消失。
3. **路径安全** —— 槽位 id 必须过 `SaveFormat.is_valid_slot_id`，
   杜绝 `../` 穿越。

### 一个踩过的坑

Godot 的 `JSON.parse_string` 会把**所有数字都读成 float**，于是写入时是 int 的
`1760000000`，读回变成 `1760000000.0`，两次 `stringify` 结果不同、校验和永远对不上。
解法是在算校验和之前先跑 `SaveGame._normalize()`，把"没有小数部分的浮点"压回 int。

### 存档位置

```
%APPDATA%\Godot\app_userdata\管制模拟器\saves\slot_<id>.json
```

槽位：`manual_1..8`（手动）、`auto_1..3`（自动）。

|---|---|
| `F9` | 生成一份演示存档（仅 DEBUG） |
| `F10` | 把存档目录与列表打印到控制台 |
| `--open=load` | 启动后直接打开载入界面 |
| `--auto-load=<slot>` | 启动 1 秒后自动载入指定槽位（用于截图验证） |
| `--auto-load=<slot> --open=save` | 载入后顺带打开保存对话框（截图用） |

## 版本与发布（按版本号分支，不覆盖旧版本）

每个版本都固定成一个独立分支 `vX.Y.Z` 和一个同名 tag，**创建后永不再改动**，
所以任何一版都能随时取回：

```
main       最新版本（持续开发）
v0.0.1     已固定，不再改动
v0.0.2     已固定，不再改动
v0.1.0     已固定，不再改动
v0.1.1     已固定，不再改动
v0.1.2     已固定，不再改动
v0.1.6     已固定，不再改动
```

版本号只有一个来源：`core/version.gd` 里的 `MAJOR / MINOR / PATCH`。

发布流程：

1. 改 `core/version.gd` 把版本号加一
2. 提交所有改动（工作区必须干净）
3. 运行 `powershell -ExecutionPolicy Bypass -File tools\release.ps1`

脚本会读出版本号，建立并推送 `vX.Y.Z` 分支与 tag。
**如果该版本分支或 tag 已存在，脚本直接拒绝退出**（不会用 -f 覆盖）。

先看会发生什么、不真正推送：

```
powershell -ExecutionPolicy Bypass -File tools\release.ps1 -DryRun
```
